## What this step changes, and what the previous one did

The previous branch moved the driver **out of the module and into
`output-zig/purzig_entry.zig`**. It stopped one step short: the emitter still
owns a program. The emitter must not write a program *at all* — the thing that
wants an executable is the build helper, so the driver belongs there, in the
build cache, and never in the project's `output-zig/`.

| file | change |
|---|---|
| `compiler/src/Zig/Emit.purs` | `emitEntry`, `entryBody`, `entryMain`, `entryFile` and `mainModule` **deleted**, along with every line of driver text. The module now exports `emitModule` only. No generated `<Module>.zig` has ever contained `main`; now nothing in `compiler/src` does either. |
| `compiler/src/Main.purs` | the entry file write is gone. `finish` writes `output-zig/manifest.json` once, describing the modules on disk plus which one exports `main` and how its export is spelled. No `entry_file` key. |
| `build/purzig.zig` | `addExecutable` writes the program with `b.addWriteFiles()`, roots the executable at that generated file, and binds the main module as an import named `purs_main`. `Options.main_module` keeps its default `"Main"` and its meaning ("the module that exports `main`"), and no longer names a root source file. |
| `docs/codegen.md`, `docs/how-is-zig-generated.md` | entry-point section, manifest schema and pipeline diagram updated; the driver text is reproduced verbatim in `codegen.md` |
| `docs/handoff-entry-deletion-2026-10-25.md` | this file |
| `runtime/**`, `build.zig`, `build.zig.zon`, `spago.yaml`, `packages.json`, `example/**`, `compiler/dist/bundle.js` | **untouched** |

Resulting emitter output: `output-zig/<Module>.zig` per module,
`output-zig/<Module>.ffi.zig` where a module has foreign imports, and
`output-zig/manifest.json`. Nothing else. No program, no entry file, no
`std.process` / `rt.ProcessInit` in any generated module.

## (i) The driver text, and where it now lives

**Before** — rendered by `Zig.Emit.emitEntry` into
`output-zig/purzig_entry.zig` (branch `0728ec1`); and, before that, appended by
`Zig.Emit.emitModule` to the module `Main` itself, calling `@"ps.main"()` as a
sibling decl.

**Now** — `build/purzig.zig`, `const program_source` (file scope, just above
`addExecutable`), written by `b.addWriteFiles()` into the build cache as
`purzig_entry.zig`:

```zig
// GENERATED by purzig's build helper. Do not edit.
//
// The program. This file is the executable's root, not a module:
// every output-zig/<Module>.zig is a module, and none of them knows
// which one exports `main`. It is written into the build cache, so
// nothing lands in the project's output-zig/ but modules.
//
// `purs_main` is the module that exports `main` (Options.main_module),
// bound by the build helper under a fixed import name.

const std = @import("std");
const rt = @import("runtime");
const purs_main = @import("purs_main");

// The entry point is chosen at comptime, so this file is identical for
// every target. Zig analyses what is REFERENCED, not what runs, so the
// native half below must not be reachable from a freestanding build:
// that target has no process, no `Io`, no console and no panic printer.
//
// Native: zig 0.16 hands `main` an `Io` and a process-lifetime arena,
// both wrapped in the type its start code passes in. That type is spelled
// `rt.ProcessInit` so it does not appear in generated sources, and so a
// freestanding target -- where it does not exist -- has one place to say
// so.
fn mainNative(init: rt.ProcessInit) !void {
    rt.init(init.io, init.arena.allocator());
    _ = try rt.runEffect(try purs_main.@"ps.main"());
}

// Freestanding: no process, so no `Io`, no arena and no console. Nothing
// can run until a host binds memory through `rt.initAlloc`, so the start
// function traps instead of pretending the program ran.
fn mainFreestanding() void {
    @trap();
}

pub const main = if (rt.freestanding) mainFreestanding else mainNative;

// The freestanding seam: a host calls this once it owns the memory.
// Deliberately unreferenced -- zig analyses only what is referenced, and
// every console primitive this program uses is native-only.
pub fn runWithAllocator(allocator: std.mem.Allocator) rt.Error!void {
    rt.initAlloc(allocator);
    _ = try rt.runEffect(try purs_main.@"ps.main"());
}
```

Byte-identical, with exactly two intended differences:

1. **The import line and the two call sites.** On `0728ec1` the emitter wrote
   `const @"mod.Main" = @import("Main.zig");` and called
   `@"mod.Main".@"ps.main"()`. Here the main module is a *module*, not a file
   next door: `const purs_main = @import("purs_main");` and
   `purs_main.@"ps.main"()`. Both `runEffect` call sites changed together; no
   `try` was added or removed.
2. **Where it lives.** The build cache (`WriteFile` step output), not
   `output-zig/`.

Everything from the blank line before `// The entry point is chosen at comptime`
to the final `}` of `runWithAllocator` was copied verbatim — 31 lines, checked
with a mechanical `diff` of the two texts (expected text extracted from
`git show HEAD:compiler/src/Zig/Emit.purs`'s `entryBody`, actual text extracted
from the multiline literal). Same `main` signature (`fn mainNative(init:
rt.ProcessInit) !void`), same `rt.init(init.io, init.arena.allocator())`, same
two `try`s, same freestanding `mainFreestanding() void { @trap(); }`, and the
fallback line is unchanged character for character:

```zig
pub const main = if (rt.freestanding) mainFreestanding else mainNative;
```

That `@trap()` arm cannot be dropped: Zig's `std/start.zig` keys on
`@hasDecl(root, "main")`, so a root without a `main` decl does not compile as an
executable.

### Why the text may not change

`sophos/purzig-template` (a different repository, not visible from this
environment) asserts the program's exact stdout in its own `test-e2e` — it is
the parity gate. The move therefore changes **where** the driver lives, never
**what it does**: same stdout, same exit status, same artifacts.

## (ii) The exact import wiring in `build/purzig.zig`

`addExecutable`, section 3:

```zig
const write_program = b.addWriteFiles();
const program = write_program.add("purzig_entry.zig", program_source);

const root = b.createModule(.{
    .root_source_file = program,
    .target = opts.target,
    .optimize = opts.optimize,
});
root.addImport("runtime", runtime);

const purs_main = b.createModule(.{
    .root_source_file = project.path(b, b.fmt("output-zig/{s}.zig", .{opts.main_module})),
    .target = opts.target,
    .optimize = opts.optimize,
});
purs_main.addImport("runtime", runtime);
root.addImport("purs_main", purs_main);

const exe = b.addExecutable(.{
    .name = opts.name,
    .root_module = root,
});
exe.step.dependOn(&codegen.step);
```

Three points:

- `purs_main` is a **module** whose root file is
  `output-zig/<main_module>.zig`; the program reaches it by the fixed import
  name `purs_main`. The generated modules still `@import("runtime")` and import
  each other by relative filename, and a file imported by relative path belongs
  to the module that owns the importing file — so binding `runtime` on
  `purs_main` covers `Main.zig` and everything it transitively imports, exactly
  as binding it on the old root did.
- The entry file's `LazyPath` comes from `addWriteFiles()`, so Zig orders the
  write before the compile by data dependency. `exe.step.dependOn(&codegen.step)`
  is still needed and still present: the module files are source-tree paths that
  `spago build` creates, so nothing else would order codegen before the compile.
- `output-zig/manifest.json` is **not** parsed here. The helper hardcodes the
  convention (fixed import name, `opts.main_module`, fixed cache filename); the
  manifest exists for tooling.

## (iii) The manifest

Written once, after every module, by `Main.finish` → `Main.renderManifest`:

```json
{
  "main_module": "Main",
  "main_export": { "name": "main", "zig": "@\"ps.main\"", "kind": "effect-thunk" },
  "modules": [
    { "name": "Main", "file": "Main.zig", "ffi": null },
    { "name": "Data.Semiring", "file": "Data.Semiring.zig", "ffi": "Data.Semiring.ffi.zig" }
  ]
}
```

| field | meaning |
|---|---|
| `main_module` | name of the module that exports `main` (`"Main"`), or `null` if none was emitted. Matches `Options.main_module`'s default and `Main.mainModule`. |
| `main_export` | how to reach `main`: `name` = the PureScript export (`"main"`), `zig` = the Zig identifier (`Ident.topLevel "main"` = `@"ps.main"`), `kind` = `"effect-thunk"`, i.e. an `Effect` thunk that is *called* to run the program. `null` when `main_module` is. |
| `modules[]` | one row per generated `.zig` module, in emission (dependency) order: `name`, `file`, and `ffi` — the `.ffi.zig` filename when one was actually written, else `null`. Answered by the filesystem, not by the module's foreign set, because the manifest promises *files*. |
| ~~`entry_file`~~ | **removed.** No file on disk is a program any more, and the build helper does not read the manifest. |

With no module exporting `main`:

```json
{
  "main_module": null,
  "main_export": null,
  "modules": [
  ]
}
```

Both forms are valid JSON (`, "ffi": null` and `null` are literals; `@"ps.main"`
is escaped as `"@\"ps.main\""` via `Ident.stringLit`). **This manifest is
constructed from the emitter's data structures by hand — it is unexecuted.**
Criterion 6 is what a human runs to confirm it.
