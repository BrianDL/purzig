## What works right now

`zig build run` compiles `purs/example/src/Main.purs` to a native binary that prints `Hello, Zig`. The user edited the PureScript string, rebuilt, and the change appeared in the output — the pipeline is genuinely driven by source, not a stub.

Generated output for the example, verbatim:

```zig
// GENERATED by purs-backend-zig from src/Main.purs. Do not edit.
const std = @import("std");
const rt = @import("runtime");
const @"mod.Zig.Prelude" = @import("Zig.Prelude.zig");

fn @"ps.greet.lam0"(env: []const rt.Value, @"v.name": rt.Value) rt.Value {
    _ = env;
    return rt.apply(rt.apply(@"mod.Zig.Prelude".@"ps.concatString"(), rt.Value.mkString("Hello, ")), @"v.name");
}
pub fn @"ps.greet"() rt.Value {
    return rt.Value.mkClosure(@"ps.greet.lam0", rt.no_env);
}
pub fn @"ps.main"() rt.Value {
    return rt.apply(@"mod.Zig.Prelude".@"ps.log"(), rt.apply(@"ps.greet"(), rt.Value.mkString("Zig")));
}
pub fn main(init: std.process.Init) !void {
    rt.init(init.io, init.arena.allocator());
    _ = rt.runEffect(@"ps.main"());
}
```

Implemented CoreFn nodes: `Lit` (all seven literal forms), `Var`, `Abs` (with free-variable analysis and lambda lifting), `App`, `Accessor`, `Constructor`, non-recursive `Let`, module-level `NonRec`/`Rec`, foreign re-exports, import graph, entry point.

Not implemented — each returns a `Left` naming itself, and `Main.purs` reports and skips the module rather than aborting: **`Case`**, **`ObjectUpdate`**, **recursive `let`**.

## Decisions (settled — do not relitigate)

- **One boxed `Value` for everything.** CoreFn is untyped; v0 does no type-directed codegen. Unboxing is a later pass.
- **One-argument closures.** CoreFn is fully curried, so `rt.apply` needs no arity analysis.
- **Flat positional closure environments** — `[]const Value` indexed by position, not a generated struct per lambda. Validated in practice: currying in the FFI is `env[0].asString()`, with no casts.
- **Top-level bindings are nullary functions**, not constants. `rt.apply` allocates, so a `const` would need to be comptime-known and a lazy global would need init ordering. Recomputation is free because PureScript is pure. purerl does the same. Memoising is a known later item.
- **Foreign re-exports are also nullary functions**, so every top-level reference the emitter produces looks identical — `@"ps.f"()` — whether foreign or generated. The emitter can't distinguish them at a use site.
- **The `ffi` module keys on PureScript module name**, not package name: `ffi.@"Zig.Prelude"`. CoreFn carries no package information.
- **Identifier scheme:** `@"ps.f"` top-level, `@"v.x"` local, `@"ps.f.lamN"` lifted lambda, `@"mod.A.B"` imported module. A dot cannot appear in an unquoted Zig identifier, so these can never collide with Zig keywords, std, or `main`. Note `@"main"` and `main` are the *same* identifier — the `ps.` prefix is what prevents that collision.
- **`zig-prelude` has zero dependencies**, declaring its own `Unit` and `Effect`. Depending on the real prelude would drag type-class dictionaries into the first program, requiring records + `Accessor` + `Case` before anything runs at all. That ordering problem, not the FFI count (~50 mostly one-line functions), is why it's deferred.
- **Behavioural tests, not golden diffs.** `expectStdOutEqual` against `"Hello, Zig\n"`. A text diff broke on comments and on any edit to `Main.purs`. `purs/example/src/Main.purs` is now a fixture; use a second module as a scratchpad.
- **Arena that never frees**, borrowed from `init.arena`. Real memory management is a v2 problem.
- **Backend written in PureScript, not Zig** — keeps `purescript-backend-optimizer` reachable.
- **Two Spago workspaces**, because `workspace.backend` is per-workspace. `purs/lib/zig-prelude` has no `workspace:` key so it can be pulled into either.
- **No `build.zig.zon`.** Nothing fetches an external Zig package.
- **devenv provisions everything; nothing global.**

## Hard-won gotchas (all cost a build cycle)

- **Never name anything `bind` or `discard` in PureScript.** Do-notation desugars to functions of those names; a parameter shadowing one breaks every `do` block in scope, and the error points at the do block rather than the shadowing name. Both were hit. There's a warning comment at the top of `Zig/Emit.purs`.
- **Zig forbids a function parameter shadowing a container-level declaration.** `fn init(io: std.Io)` collides with `pub fn io()` in the same file.
- **`spago bundle`, not `spago build`.** Only `bundle` produces `bundle.js`, which is what `backend.cmd` points at. Bundling implies compiling, so it's one step.
- **`bundle.type` is `app`**, not `application`.
- **esbuild is a hard dependency** of `spago bundle` and must be in `devenv.nix`.
- **`"type": "module"`** in `purs/compiler/package.json` silences a Node ESM warning on every backend invocation.
- CoreFn traps, all handled in `Decode.purs`: `moduleName` is an array of segments; `ObjectLiteral`'s value is an array of `[key, value]` *arrays*, not an object; `Qualified` has no tag (presence of `moduleName` means global); `CaseAlternative` changes its key name with `isGuarded`; `Constructor` in an expression carries bare strings but `ConstructorBinder` carries Qualified objects; every module imports a bogus `Prim`.

## Dead ends (do not repeat)

- **Routing PureScript → C++/Go → Zig** via `purescript-native`: Zig can't import C++ headers or Go directly; each hop needs a hand-written `extern "C"` shim and you inherit two runtimes.
- **Writing the backend compiler in Zig**: simpler build, but permanently forgoes `purescript-backend-optimizer`. User's call: *"it really sounds like it's actually needed. Let's keep it then."*
- **Global npm installs.** User: *"no globals. Also, installing the development tool IS the job of devenv."*
- **Pinned package set.** Replaced with the registry solver.
- **Golden-file diffing of generated Zig.** Too brittle; replaced with output assertions.

## Glossary

- **Backend:** the target language PureScript compiles to. Mechanically, an executable reading `corefn.json` and emitting source. Never touches the compiler.
- **CoreFn:** the compiler's untyped, fully-curried IR, emitted by `purs compile --codegen corefn`.
