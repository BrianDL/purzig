## What changed

### The calling convention is now fallible
- `Fn1` returns `value.Error!Value` where `Error = error{PsException}`. This is the single declaration that forces generated code's signatures, so **runtime and emitter changes are necessarily one commit** — they don't compile separately. (The user initially chose to split them; that turned out to be impossible.)
- Emitter: top-level bindings, foreign re-exports and all three lifted-lambda forms return `rt.Error!rt.Value`; `App` emits `(try rt.apply(f, x))`; a top-level `Var` emits `(try @"ps.f"())`.
- **Every emitted `try` is parenthesised.** Zig's `try` binds looser than postfix field access, so `try f().field("k")` parses as `try (f().field("k"))` and fails. Output is paren-heavy as a result; fixing that cosmetically means tracking whether an expression is about to be projected, which belongs after step 2.
- `curry.zig` needed only its `run` signature changed. `@call` is untouched: Zig coerces `T` to `E!T` on return, so one call site accepts both plain and fallible FFI functions, and no existing prelude FFI needed editing.

### New `Value` variant and runtime surface
- **`ref: *Value`** — the only mutable thing in the runtime, backing `Effect.Ref`. A one-field record cannot work: `mkRecord` copies, so a write would update a copy nobody holds. `newWithSelf` additionally needs the cell to exist before its contents.
- New in `root.zig`: `Error`, `throwValue`, `takeError`, `newRef`, `newLazy`, `setLazyInit`, `forceLazy`, `writeLineErr`.
- **`runtime/lazy.zig` (new).** A three-state cell (`waiting`/`pending`/`forcing`/`done`) as a `ref` holding a tagged `data`, so no further `Value` variant was needed.

### Laziness for recursive `let`
**Supersedes** the 08-07 decision *"Only `Abs` members are supported in a recursive `let`"* and `codegen.md`'s matching note. Non-`Abs` members now get a lazy cell. `Control.Lazy.fix` was the first real package to hit the old restriction.

- The compiler's own `applyLazinessTransform` is a **Haskell API** available only to backends embedding the compiler as a library (purerl can; we read `corefn.json` and cannot). The 0.15.0 release notes specify the fallback and the exact runtime contract, including that backends should make the error appropriate for their target — so a cycle panics rather than throwing a catchable exception.
- Restricting the cheap lifted-closure path to `Abs` members is the "light analysis" the notes explicitly sanction, not an invention.
- **The load-bearing rule: reading a lazy binding forces it; capturing it does not.** `Var` wraps in `rt.forceLazy`; `scopeText`, which builds every capture list, yields the bare cell. Backwards, and `go = defer \_ -> f go` forces during its own initialisation and hits the cycle panic — the exact case the cell exists for.
- The `lazy` flag lives on the scope **entry** (`type Scoped = { ps, zig, lazy }`), not in a set on `Ctx`, so shadowing is handled by `lookupEntry` finding the innermost entry rather than by pruning a set at every binding site.

### Two emitter bugs found by real library code
- **Unused scrutinee temporary** (`Data.Functor.Invariant`): a multi-scrutinee `case` whose column is `_` in every *reachable* alternative. Now emits `_ = @"v.c.N.I";`. Discarded rather than omitted, because the scrutinee is still an expression and omitting it changes evaluation order.
- **Shadowing across alternatives** (`Data.Maybe`): a guarded `VarBinder` alternative binds a name *and* falls through, so the next alternative's binding collided. Each alternative that can fall through now gets its own Zig block — the structural fix, matching Zig scope to PureScript scope, rather than suffixing names. Alternatives that can't fall through stay unbracketed so the case block still ends in an unconditional `break`.

## Decisions (settled — do not relitigate)

- **A registry package with no `foreign import` needs no vendoring.** Nothing references its `.js`, so the registry copy compiles through the backend untouched. `either`, `maybe`, `invariant`, `newtype` and `safe-coerce` all come straight from the registry. **Supersedes** the 08-08 implication that any registry package fails with `MISSING FFI`.
- **`Error` is a data constructor**, `mkData("Error", &.{message, name, cause})`, not a record — nothing in PureScript projects it structurally, since `message` and `name` *are* the foreign imports.
- **`catchException` uses `if (...) |v| ... else |_| ...`, not `catch`.** The recovery branch is itself fallible (a handler may throw), and `a catch b` requires `b` to be the unwrapped type.
- **`EffectFnN` is a compatibility shim, not an optimisation.** There is no N-ary function value here, so an `EffectFnN` is a curried chain that fires on saturation instead of waiting for a unit thunk. `mkEffectFnN` forces, `runEffectFnN` defers; both fall out of `rt.curry`/`rt.effect`.
- **Six of `Effect.Console`'s twelve are no-ops** — `time`/`timeLog`/`timeEnd`, `group`/`groupCollapsed`/`groupEnd`, `clear`. `warn` and `error` go to stderr, matching Node. Timers would need a label→timestamp table and a clock, which 0.16 routes through `Io`.
- **`forE`'s counter is `i64`, not wrapping `i32`.** A wrapping counter spins forever when `hi` is `top`; JavaScript's Number has no such edge.
- **The fixture self-diagnoses.** `Scratch.purs` prints `Hello, <label>` naming the first failed check rather than an undifferentiated wrong string. Cost five lines, localised a failure in one build cycle.

## Constraints and facts

- **`extraPackages` is not `dependencies`.** Listing a package under `extraPackages` only redirects where it resolves from; importing it directly requires a `dependencies` entry too. Cost one build cycle with `control`.
- The arena never frees, so a `Ref` written in a loop costs memory proportional to the number of *writes*. `forE`/`whileE`/`foreachE` are the first constructs that make unbounded allocation reachable without blowing the stack first.
- PureScript anonymous arguments must be a **direct** argument of the enclosing expression: `(_ + i + 1)` is rejected, `(_ + 1)` is fine.
- Vendoring must copy `src/`, not `src/<TopLevelNamespace>/`. A module's namespace does not determine its package — `Data.Monoid.Alternate` ships in `purescript-control`, and `Effect.Class.Console` in `purescript-console`.
- `Data/Ord.zig`'s `compareValues` already has a catch-all, so adding the `ref` variant did not break it.
